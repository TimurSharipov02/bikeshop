# Обмен с 1С

Две отдельные "ручки" (адреса), которые дёргает не человек через браузер, а
сама 1С — кнопкой в своей программе или по расписанию. Обе защищены одним
секретным ключом `INTEGRATION_1C_KEY`, который нужно один раз задать в
настройках Vercel (см. ниже) и сообщить тому, кто настраивает 1С.

Сайт: `https://bikeshop-chi.vercel.app`

## 1. Как задать ключ в Vercel (один раз)

1. Придумайте или сгенерируйте длинную случайную строку — это и будет
   ключ. Варианты:
   - Если есть доступ к терминалу/командной строке: `openssl rand -hex 24`
     — выведет строку вроде `a1b2c3d4e5f6...`, её и используйте.
   - Если терминала нет: придумайте длинную фразу без пробелов из
     случайных слов и цифр, например `velo-1c-2026-krutaya-fraza-99231`.
     Чем длиннее и бессмысленнее — тем лучше, это не пароль, который
     нужно запоминать, его один раз скопируют в 1С и в Vercel.
2. Зайдите на `vercel.com`, войдите в свой аккаунт.
3. Откройте проект `bikeshop` (или как он у вас называется в списке
   проектов).
4. Сверху — вкладка **Settings** (Настройки).
5. В левом меню — **Environment Variables** (Переменные окружения).
6. Поле **Key** (имя): введите `INTEGRATION_1C_KEY` — ровно так, заглавными
   буквами, с подчёркиваниями.
7. Поле **Value** (значение): вставьте ключ, который придумали в шаге 1.
8. Ниже — где отмечены окружения (**Production / Preview / Development**):
   достаточно отметить **Production** (это и есть боевой сайт
   `bikeshop-chi.vercel.app`).
9. Нажмите **Save**.
10. Важно: переменная окружения применяется только к новым сборкам сайта.
    Откройте вкладку **Deployments**, у самого верхнего (последнего)
    деплоя нажмите на три точки `···` → **Redeploy** → подтвердите. Через
    1–2 минуты новая версия с ключом будет на сайте.
11. Сохраните ключ в надёжном месте (например, в заметке в телефоне) и
    передайте его тому, кто настраивает обмен на стороне 1С — по
    возможности не через открытый чат, а лично или голосом.

Если понадобится сменить ключ — повторите шаги 6-10 с новым значением
(старый перестанет работать сразу после передеплоя, так что меняйте ключ
и на стороне 1С одновременно).

## 2. Выгрузка выполненных работ → в 1С (`/api/1c-export`)

Это работы, за которые сайт хочет отчитаться в 1С: велосипед уже выдан
клиенту, запчасти списаны, сумма за работу посчитана — и это ещё не было
забрано предыдущим запросом.

### Шаг 1 — получить список (GET)

Запрос:
```
GET https://bikeshop-chi.vercel.app/api/1c-export?key=ВАШ_КЛЮЧ
```

Ответ (пример):
```json
{
  "orders": [
    {
      "number": "V123",
      "handedOverAt": "2026-09-20T10:00:00.000Z",
      "clientName": "Иван Петров",
      "clientPhone": "+79991234567",
      "bikeName": "Trek Marlin 7",
      "parts": [
        { "sku": "TUBE-26", "name": "Камера 26\"", "qty": 1 },
        { "sku": "BRK-PAD-01", "name": "Колодки дисковые", "qty": 2 }
      ],
      "laborSum": 1500,
      "exportedTo1C": false
    }
  ]
}
```
`parts` — запчасти по артикулу (`sku` — тот же артикул, что и в остатках,
см. ниже), `laborSum` — общая сумма за работу одним числом (без разбивки по
видам работ — оплата труда мастеров идёт через кассу отдельно).

Для сверки/отладки можно добавить `&all=1` — тогда вернутся вообще все
выданные обращения, включая уже забранные раньше (у каждого будет видно
поле `exportedTo1C: true/false`). Это ничего не помечает и не портит,
можно вызывать сколько угодно раз — удобно, чтобы сверить полную историю,
если что-то пошло не так при первой настройке.

### Шаг 2 — подтвердить, что забрали (POST)

После того как 1С обработала полученный список, нужно сообщить сайту,
какие номера обращений забраны — иначе они придут повторно при следующем
запросе.

Запрос:
```
POST https://bikeshop-chi.vercel.app/api/1c-export
Content-Type: application/json

{ "key": "ВАШ_КЛЮЧ", "numbers": ["V123", "V124"] }
```

Ответ:
```json
{ "ok": true, "marked": 2 }
```
Повторный POST с теми же номерами ничего не портит (`marked` просто будет
0 для уже отмеченных) — так что если 1С не уверена, что запрос дошёл в
прошлый раз, можно смело повторить.

## 3. Приём остатков от 1С → на сайт (`/api/1c-stock`)

1С полностью заменяет список остатков на сайте своим текущим списком —
это должна быть выгрузка ВСЕХ позиций, а не только изменившихся, иначе
позиции, отсутствующие в присланном списке, будут считаться удалёнными.

Запрос:
```
POST https://bikeshop-chi.vercel.app/api/1c-stock
Content-Type: application/json

{
  "key": "ВАШ_КЛЮЧ",
  "items": [
    { "sku": "TUBE-26", "name": "Камера 26\"", "qty": 12, "unit": "шт",
      "price": 350, "group": "WHL", "maxQty": 2 },
    { "sku": "BRK-PAD-01", "name": "Колодки дисковые", "qty": 40, "unit": "шт",
      "price": 900, "group": "BRK", "maxQty": 0 }
  ]
}
```
Поля:
- `sku` — артикул (может быть пустым, если у позиции его нет, но тогда
  обязательно `name`);
- `name` — название;
- `qty` — остаток числом;
- `unit` — единица измерения ("шт", "м" и т.п.), не обязательно;
- `price` — цена за единицу, не обязательно (0, если нет);
- `group` — код узла велосипеда, к которому относится запчасть, один из:
  `WHL` (колёса), `BRK` (тормоза), `BB` (каретка), `STR` (рулевая),
  `FRM` (рама), `DRV` (трансмиссия), `TCH` (посадка/контактные точки),
  `WSH` (мойка и консервация) — можно оставить пустым, тогда позиция
  просто не попадёт ни в один фильтр по узлу в приложении;
- `maxQty` — потолок количества этой позиции за одну операцию списания
  (например, спицы — 64, цепь — 1), можно оставить пустым/0.

## 6. Ручная сверка из админки сайта (без ключа)

В самой админке (Админка → «Синхронизация с 1С») есть экран со списком
обращений, ещё не помеченных выгруженными, и кнопка «Пометить все как уже
выгруженные». Он для одного случая: часть обращений уже была занесена в
1С вручную (до того как заработала автоматическая выгрузка, или в обход
неё) — кнопка отмечает их так, чтобы автоматика потом не притащила их
ещё раз. Не для повседневного использования: если 1С подключена и
работает штатно, список тут обычно пуст.

Ответ:
```json
{ "ok": true, "count": 2, "updatedAt": "2026-09-24T12:00:00.000Z" }
```

Если 1С случайно пришлёт пустой список, а на сайте остатки не были
пустыми, сайт откажет ошибкой 400 (чтобы не обнулить остатки из-за сбоя
выгрузки на стороне 1С). Если остатки действительно нужно обнулить —
добавьте в запрос `"force": true`.

Ручной способ (вставка списка в админке, экран «Запчасти» →
«Импорт списком») остаётся как резервный вариант — им можно пользоваться,
если обмен с 1С ещё не настроен или временно не работает. На экране
«Запчасти» рядом с временем обновления теперь видно, откуда взяты текущие
цифры — «· из 1С» или «· вручную».

## 4. Проверка вручную (curl)

Замените `ВАШ_КЛЮЧ` на реальный ключ. Эти команды можно попросить
выполнить того, кто настраивает 1С, чтобы проверить связь до того, как
подключать саму 1С.

```bash
# список работ, ожидающих выгрузки
curl "https://bikeshop-chi.vercel.app/api/1c-export?key=ВАШ_КЛЮЧ"

# подтвердить выгрузку конкретных номеров
curl -X POST "https://bikeshop-chi.vercel.app/api/1c-export" \
  -H "Content-Type: application/json" \
  -d '{"key":"ВАШ_КЛЮЧ","numbers":["V123"]}'

# отправить остатки
curl -X POST "https://bikeshop-chi.vercel.app/api/1c-stock" \
  -H "Content-Type: application/json" \
  -d '{"key":"ВАШ_КЛЮЧ","items":[{"sku":"TUBE-26","name":"Камера 26\"","qty":12,"unit":"шт","price":350,"group":"WHL"}]}'
```

## 5. Если что-то не отвечает

- Ответ `{"error":"storage not configured"}` — хранилище (Redis) не
  настроено в Vercel, это отдельная проблема, не про 1С, нужно
  разбираться отдельно.
- Ответ `{"error":"интеграция с 1С не настроена (нет INTEGRATION_1C_KEY)"}`
  — ключ не задан в Vercel или сайт не передеплоился после того, как его
  задали (см. шаг 10 в разделе 1).
- Ответ `{"error":"неверный ключ"}` — ключ в запросе от 1С не совпадает с
  тем, что в Vercel; сверьте, что скопировали без лишних пробелов.
