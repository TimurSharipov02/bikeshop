# Обмен с 1С

Две отдельные "ручки" (адреса), которые дёргает не человек через браузер, а
сама 1С — кнопкой в своей программе или по расписанию. Обе защищены одним
секретным ключом `INTEGRATION_1C_KEY`, который нужно один раз задать в
настройках Vercel (см. ниже) и сообщить тому, кто настраивает 1С.

Сайт: `https://bikeshop-chi.vercel.app`

## Кассовое рабочее место (УНФ 3.0)

У владельца установлена «Управление нашей фирмой» 3.0.6.145 на платформе
8.3.25.1445 в файловой базе. В списке подключаемого оборудования видны
сканер «1С:Сканер штрихкода (Native Api)», ККТ АТОЛ (ОФД 1.2), терминалы
ИНПАС UNIPOS и Aisino. Нужно выяснить, какой из эквайринговых терминалов
работает на кассе: наличие настройки в списке не означает, что она активна.
В рабочем месте кассира УНФ услуги и товары находятся в одном чеке
(наблюдавшийся пример: услуга «Набор ремонт 2» и камера). Бумажные
штрихкоды под экраном выбирают отдельные услуги мастеров в УНФ: «Набор
ремонт 2» относится к Тимуру, цену услуги можно изменить при продаже.
Считанные сканером соответствия: Тимур `2000999796289`, Эльнар
`2000999806483`, Сергей `2000999796371`. При смене кассовых карточек
штрихкод можно указать в админке, в настройках конкретного мастера;
это значение имеет приоритет над соответствием по имени. Сайт передаёт
`laborLines` по мастерам с их точной стоимостью работ и штрихкодом услуги;
номенклатуру услуги мастера и товары нужно сопоставить в УНФ до оплаты.
`sku` сайта сам по себе не является штрихкодом 1С.

На кассе проверен уже пробитый чек ККМ №7829: список показывает статус
«Чек пробит» и фискальный номер с ведущими нулями. Команда «Еще» →
«Повторная печать чека» выдаёт копию с полями `ФН №`, `ФД №` и `ФП`.
Их значения относятся к **этому** чеку; повторная печать не создаёт новый
чек и не подтверждает оплату произвольного обращения. Номер ФД на бумаге
может отображаться без ведущих нулей, поэтому для идентификатора используем
сочетание ФН, ФД и ФП конкретного пробитого чека.
При подтверждении сайт принимает только цифровые реквизиты, приводит ФД и
ФП к одной записи без ведущих нулей и запрещает повторное использование
того же сочетания в другом обращении.

Подготовлен отдельный контракт **до выдачи**: `api/1c-checkout`. Он не
запускает терминал и ККТ дистанционно. Обработка на компьютере с 1С должна
подобрать номенклатуру/услуги, принять оплату и фискализировать чек штатными
средствами УНФ, после чего сообщить сайту реквизиты чека. При ошибке чека
подтверждение отправлять нельзя. При ошибке ответа сайта после успешного
чека обработка должна повторить подтверждение с теми же реквизитами, не
пробивая чек второй раз.

**Режим пока выключен.** Для проверки чтения из обработки без блокировки
обычной выдачи задайте в Vercel секрет `INTEGRATION_1C_KEY` и
`INTEGRATION_1C_PREVIEW=1`, затем передеплойте. Это разрешит только GET
`/api/1c-checkout` с правильным ключом; POST для подтверждения оплаты
по-прежнему вернёт 503, а сайт продолжит обычную выдачу. Проверка
должна выполняться на завершённом, ещё не выданном обращении. После неё
отключите `INTEGRATION_1C_PREVIEW`.

Сначала проверьте обработку на кассовом компьютере и соответствие
номенклатуры. Только после проверки полного сценария задайте в Vercel
`INTEGRATION_1C_CHECKOUT=1` и передеплойте. Пока переменной нет,
действует существующая кнопка выдачи, а POST кассового API отвечает 503.
GET без режима просмотра также отвечает 503.
При включении сайт запрещает обычную выдачу через `/api/db`, экран
«Оплата» ждёт подтверждения 1С и предлагает обновить статус.

### Протокол обработки УНФ

1. Получить завершённое обращение до оплаты:

   ```http
   GET /api/1c-checkout?number=V123
   X-1C-Key: <секрет из INTEGRATION_1C_KEY>
   ```

   Ответ `{"order":{"number":"V123","parts":[...],
   "laborLines":[{"masterId":"...","masterName":"Тимур","serviceBarcode":"2000999796289","amount":1500}],"laborSum":1500,
   "partsSum":2150,"total":3650,"quoteId":"..."}}`.
   `quoteId` действует для этого состава и суммы. Цена в чеке должна
   совпасть с `total`. Каждую строку `laborLines` нужно провести через
   услугу соответствующего мастера в УНФ по её штрихкоду, выставив цену
   `amount`; детали идут отдельными товарными позициями. Если у мастера
   не указан и не распознан штрихкод услуги, кассовый API отклоняет
   обращение, чтобы не приписать выручку другому мастеру. `laborSum`
   служит проверкой суммы по всем мастерам. Если есть запчасти без артикула
   или `unallocatedPartsSum > 0`, кассир должен сопоставить позиции до чека.

2. После успешного платежа и фискализации отправить подтверждение:

   ```http
   POST /api/1c-checkout
   Content-Type: application/json
   X-1C-Key: <секрет из INTEGRATION_1C_KEY>

   {"number":"V123","quoteId":"...","total":3650,
    "receipt":{"fn":"номер ФН","fd":"номер ФД","fp":"фискальный признак"}}
   ```

   Только тогда сайт фиксирует оплату и выдачу одним действием и отмечает
   чек уже созданным в 1С: повторная выгрузка через `/api/1c-export`
   его не продублирует. Повтор
   запроса с тем же чеком безопасен (`alreadyConfirmed: true`), чек для
   другого обращения отклоняется. При ошибке 409 состав/сумма изменились
   или обращение уже выдано: нужно сверить чек и данные вручную, не
   принимать повторный платеж автоматически.

На кассовом компьютере создана внешняя обработка `ВелотерраКасса.epf` с
управляемой формой и тремя реквизитами: `НомерОбращения` (строка 40),
`Ключ1С` (строка 128, поле ввода в режиме пароля), `Сводка` (строка без
ограничения длины, многострочная, только просмотр). На форму добавлена
команда `ПолучитьОбращение`, её действие связано с одноимённой процедурой.
Исходный модуль первого этапа прошёл синтаксическую проверку на кассовом
компьютере. Следующая версия [`onec/checkout-form.bsl`](../onec/checkout-form.bsl)
ещё **не установлена и не проверена в 1С**. Перед заменой модуля нужно
добавить к `Объект` реквизиты: `ИдентификаторРасчета` (строка 64, скрытый
элемент формы), `СуммаКОплате` (число 15,2, только просмотр), `ФН`, `ФД`,
`ФП` (каждый строка 20), `ЧекПробитИСверен` (булево). Также нужна команда
`ПодтвердитьЧек`. Модуль очищает прежний расчёт до запроса и сохраняет
идентификатор и сумму после успешной загрузки. После штатной оплаты и
фискализации в УНФ кассир сверяет чек, вводит ФН, ФД, ФП и подтверждает
оплату на сайте. При ошибке сети повторяется только подтверждение, без
повторного пробития чека. Без новых реквизитов заменять модуль нельзя.

После публикации API нужно проверить запрос из 1С на тестовом обращении.
Обработка пока не создаёт позиции продажи в УНФ, не проводит оплату и не
печатает фискальный чек. Код ручного подтверждения ещё не проверен в 1С;
он полагается на сверку кассиром и сам не ищет чек в базе УНФ. Не включайте
`INTEGRATION_1C_CHECKOUT=1` до проверки всего цикла в этой конкретной базе:
иначе выдача на сайте заблокируется, а автоматической оплаты из обработки
ещё нет.

Для завершающего этапа нужны проверенные в базе УНФ способы выбора
номенклатуры по штрихкоду, добавления позиций в рабочее место кассира,
получения реквизитов уже сформированного фискального чека и сопоставления
каждой запчасти сайта с номенклатурой УНФ. Сканирование бумажного штрихкода
услуги и возможность изменения цены подтверждены на кассе, но программные
команды УНФ для этих действий пока не проверены.

### Что подтверждено в метаданных кассовой базы

По снимкам конфигуратора для `Документы.ЧекККМ` табличная часть продажи
называется `Запасы`. В ней видны `Номенклатура`, `Характеристика`,
`Партия`, `Количество`, `ЕдиницаИзмерения`, `Цена`, `Сумма`, `СтавкаНДС`,
`СуммаНДС`, `Всего` и `Штрихкод`. Среди реквизитов шапки видны
`КассаККМ`, `КассоваяСмена`, `Организация`, `ФормаОплаты`,
`НалогообложениеНДС`, `СуммаДокумента`, `Статус` и другие.

Эти имена **не подтверждают**, что достаточно присвоить значения в
`Документы.ЧекККМ.СоздатьДокумент()`: УНФ может заполнять связанные
реквизиты и проверять смену, склад, цены, налоги и состояние оплаты своим
кодом формы. Внешняя обработка не должна записывать/проводить `ЧекККМ`
или вызывать ККТ напрямую до проверки этого сценария в копии базы.
Особенно важно, что `sku` запчасти на сайте не является ссылкой на
`Номенклатура` УНФ и не подтверждён как её штрихкод. Для автоматического
черновика нужно получить однозначное соответствие каждой позиции с
номенклатурой 1С и проверить штатный способ открытия формы чека с
предзаполнением в этой версии УНФ. До тех пор строки в `Сводка` служат
кассиру планом ввода и сверки, но не готовым чеком.

## 1. Как задать ключ в Vercel (один раз)

1. Придумайте или сгенерируйте длинную случайную строку — это и будет
   ключ. Варианты:
   - Если есть доступ к терминалу/командной строке: `openssl rand -hex 24`
     — выведет строку вроде `a1b2c3d4e5f6...`, её и используйте.
   - Если терминала нет: придумайте длинную фразу без пробелов из
     случайных слов и цифр, например `velo-1c-2026-krutaya-fraza-99231`.
     Чем длиннее и бессмысленнее — тем лучше, это не пароль, который
     нужно запоминать, его один раз скопируют в 1С и в Vercel.
2. Зайдите на `vercel.com`, войдите в свой аккаунт.
3. Откройте проект `bikeshop` (или как он у вас называется в списке
   проектов).
4. Сверху — вкладка **Settings** (Настройки).
5. В левом меню — **Environment Variables** (Переменные окружения).
6. Поле **Key** (имя): введите `INTEGRATION_1C_KEY` — ровно так, заглавными
   буквами, с подчёркиваниями.
7. Поле **Value** (значение): вставьте ключ, который придумали в шаге 1.
8. Ниже — где отмечены окружения (**Production / Preview / Development**):
   достаточно отметить **Production** (это и есть боевой сайт
   `bikeshop-chi.vercel.app`).
9. Нажмите **Save**.
10. Важно: переменная окружения применяется только к новым сборкам сайта.
    Откройте вкладку **Deployments**, у самого верхнего (последнего)
    деплоя нажмите на три точки `···` → **Redeploy** → подтвердите. Через
    1–2 минуты новая версия с ключом будет на сайте.
11. Сохраните ключ в надёжном месте (например, в заметке в телефоне) и
    передайте его тому, кто настраивает обмен на стороне 1С — по
    возможности не через открытый чат, а лично или голосом.

Если понадобится сменить ключ — повторите шаги 6-10 с новым значением
(старый перестанет работать сразу после передеплоя, так что меняйте ключ
и на стороне 1С одновременно).

## 2. Выгрузка выполненных работ → в 1С (`/api/1c-export`)

Это обращения, которые на сайте помечены выданными. Сейчас кнопка выдачи
**не проверяет оплату в 1С**: экран оплаты на сайте является заглушкой.
Поэтому получение обращения через этот API не подтверждает ни оплату,
ни создание чека, ни списание запчастей в 1С. До подключения кассового
сценария сверяйте факт оплаты в самой 1С.

### Шаг 1 — получить список (GET)

Запрос:
```
GET https://bikeshop-chi.vercel.app/api/1c-export?key=ВАШ_КЛЮЧ
```

Ответ (пример):
```json
{
  "orders": [
    {
      "number": "V123",
      "handedOverAt": "2026-09-20T10:00:00.000Z",
      "clientName": "Иван Петров",
      "clientPhone": "+79991234567",
      "bikeName": "Trek Marlin 7",
      "parts": [
        { "sku": "TUBE-26", "name": "Камера 26\"", "qty": 1, "price": 350 },
        { "sku": "BRK-PAD-01", "name": "Колодки дисковые", "qty": 2, "price": 900 }
      ],
      "laborSum": 1500,
      "partsSum": 2150,
      "unallocatedPartsSum": 0,
      "total": 3650,
      "exportedTo1C": false
    }
  ]
}
```
`parts` — запчасти по артикулу с ценой за единицу; `laborLines` — работы
по исполнителям, `laborSum` — их общая стоимость, `partsSum` — стоимость
запчастей, `total` — сумма к оплате. Поле
`unallocatedPartsSum` показывает стоимость запчастей, записанную ранее
одним числом без указания конкретной номенклатуры. Если оно больше нуля,
позиции нужно сопоставить в 1С вручную: сайт не знает их артикулы.
Если у позиции пустой `sku`, сопоставление по одному названию требует
проверки кассиром. Сканер штрихкодов работает с номенклатурой в 1С;
этот API пока не содержит штрихкодов.

Для сверки/отладки можно добавить `&all=1` — тогда вернутся вообще все
выданные обращения, включая уже забранные раньше (у каждого будет видно
поле `exportedTo1C: true/false`). Это ничего не помечает и не портит,
можно вызывать сколько угодно раз — удобно, чтобы сверить полную историю,
если что-то пошло не так при первой настройке.

### Шаг 2 — подтвердить, что забрали (POST)

После того как 1С обработала полученный список, нужно сообщить сайту,
какие номера обращений забраны — иначе они придут повторно при следующем
запросе.

Запрос:
```
POST https://bikeshop-chi.vercel.app/api/1c-export
Content-Type: application/json

{ "key": "ВАШ_КЛЮЧ", "numbers": ["V123", "V124"] }
```

Ответ:
```json
{ "ok": true, "marked": 2 }
```
Вызывайте POST только после успешного создания документа в 1С и сохраняйте
номер обращения в нём для защиты от повторной загрузки после сбоя сети.
Повторный POST с теми же номерами возвращает `marked: 0`. Если хотя бы один
номер неизвестен сайту или обращение ещё не выдано, весь запрос
отклоняется с кодом 400, остальные номера не помечаются.

## 3. Приём остатков от 1С → на сайт (`/api/1c-stock`)

1С полностью заменяет список остатков на сайте своим текущим списком —
это должна быть выгрузка ВСЕХ позиций, а не только изменившихся, иначе
позиции, отсутствующие в присланном списке, будут считаться удалёнными.

Запрос:
```
POST https://bikeshop-chi.vercel.app/api/1c-stock
Content-Type: application/json

{
  "key": "ВАШ_КЛЮЧ",
  "items": [
    { "sku": "TUBE-26", "name": "Камера 26\"", "qty": 12, "unit": "шт",
      "price": 350, "group": "WHL", "maxQty": 2 },
    { "sku": "BRK-PAD-01", "name": "Колодки дисковые", "qty": 40, "unit": "шт",
      "price": 900, "group": "BRK", "maxQty": 0 }
  ]
}
```
Поля:
- `sku` — артикул (может быть пустым, если у позиции его нет, но тогда
  обязательно `name`);
- `name` — название;
- `qty` — остаток числом;
- `unit` — единица измерения ("шт", "м" и т.п.), не обязательно;
- `price` — цена за единицу, не обязательно (0, если нет);
- `group` — код узла велосипеда, к которому относится запчасть, один из:
  `WHL` (колёса), `BRK` (тормоза), `BB` (каретка), `STR` (рулевая),
  `FRM` (рама), `DRV` (трансмиссия), `TCH` (посадка/контактные точки),
  `WSH` (мойка и консервация) — можно оставить пустым, тогда позиция
  просто не попадёт ни в один фильтр по узлу в приложении;
- `maxQty` — потолок количества этой позиции за одну операцию списания
  (например, спицы — 64, цепь — 1), можно оставить пустым/0.

## 6. Ручная сверка из админки сайта (без ключа)

В самой админке (Админка → «Синхронизация с 1С») есть экран со списком
обращений, ещё не помеченных выгруженными, и кнопка «Пометить все как уже
выгруженные». Он для одного случая: часть обращений уже была занесена в
1С вручную (до того как заработала автоматическая выгрузка, или в обход
неё) — кнопка отмечает их так, чтобы автоматика потом не притащила их
ещё раз. Не для повседневного использования: если 1С подключена и
работает штатно, список тут обычно пуст.

Ответ:
```json
{ "ok": true, "count": 2, "updatedAt": "2026-09-24T12:00:00.000Z" }
```

Если 1С случайно пришлёт пустой список, а на сайте остатки не были
пустыми, сайт откажет ошибкой 400 (чтобы не обнулить остатки из-за сбоя
выгрузки на стороне 1С). Если остатки действительно нужно обнулить —
добавьте в запрос `"force": true`.

Ручной способ (вставка списка в админке, экран «Запчасти» →
«Импорт списком») остаётся как резервный вариант — им можно пользоваться,
если обмен с 1С ещё не настроен или временно не работает. На экране
«Запчасти» рядом с временем обновления теперь видно, откуда взяты текущие
цифры — «· из 1С» или «· вручную».

## 4. Проверка вручную (curl)

Замените `ВАШ_КЛЮЧ` на реальный ключ. Эти команды можно попросить
выполнить того, кто настраивает 1С, чтобы проверить связь до того, как
подключать саму 1С.

```bash
# список работ, ожидающих выгрузки
curl "https://bikeshop-chi.vercel.app/api/1c-export?key=ВАШ_КЛЮЧ"

# подтвердить выгрузку конкретных номеров
curl -X POST "https://bikeshop-chi.vercel.app/api/1c-export" \
  -H "Content-Type: application/json" \
  -d '{"key":"ВАШ_КЛЮЧ","numbers":["V123"]}'

# отправить остатки
curl -X POST "https://bikeshop-chi.vercel.app/api/1c-stock" \
  -H "Content-Type: application/json" \
  -d '{"key":"ВАШ_КЛЮЧ","items":[{"sku":"TUBE-26","name":"Камера 26\"","qty":12,"unit":"шт","price":350,"group":"WHL"}]}'
```

## 5. Если что-то не отвечает

- Ответ `{"error":"storage not configured"}` — хранилище (Redis) не
  настроено в Vercel, это отдельная проблема, не про 1С, нужно
  разбираться отдельно.
- Ответ `{"error":"интеграция с 1С не настроена (нет INTEGRATION_1C_KEY)"}`
  — ключ не задан в Vercel или сайт не передеплоился после того, как его
  задали (см. шаг 10 в разделе 1).
- Ответ `{"error":"неверный ключ"}` — ключ в запросе от 1С не совпадает с
  тем, что в Vercel; сверьте, что скопировали без лишних пробелов.
