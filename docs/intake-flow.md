# Процесс приёмки и передачи в работу

Статус: черновик v0.1 · Дата: 2026-09-09 · Фаза 3

Описывает путь от «клиент пришёл» до «мастер начал работу». Ключевой принцип:
**мастер получает список работ структурно (чекбоксы из справочника операций),
без опоры на устный контекст.**

## Шаги

### 1. Запрос клиента

Фиксируем то, с чем пришёл клиент, его словами — коротко. Это не список работ, а
исходная жалоба («переключается плохо», «щёлкает сзади», «готовлю к гонке»).

Данные клиента: имя, **номер телефона (уникальный ключ)**, согласие на обзвон.
Данные велосипеда: тип (шоссе / гревел / МТБ), бренд, модель. Номер рамы —
опционально, отдельный учёт велосипедов пока не ведём.

### 2. Диагностика

Делается **всегда**, независимо от запроса. В идеале — самым квалифицированным
из свободных мастеров.

Проходит по чек-листу (операция `DIA-01`, при необходимости `DIA-02` / `DIA-03`).
Результат — набор отмеченных пунктов:

- что требует работы (из справочника операций → чекбоксы);
- что в норме, но на грани (рекомендации на будущее);
- ожидаемые сложности и риски (прикипело, нестандартные стандарты, износ смежных
  узлов);
- нужные запчасти и расходники.

Свободный текст — только там, где чекбокса недостаточно, и максимально короткий.

### 3. Согласование с клиентом

Из диагностики собирается смета: перечень работ (в клиентских названиях) + цены
из прайса + запчасти + срок. Клиент подтверждает состав. Что не согласовано —
в работу не идёт.

Отдельно фиксируем «уже было сломано / поцарапано до нас».

### 4. Передача мастеру

Согласованный список уходит в электронную систему как **заказ-наряд**:

- работы — чекбоксами из справочника операций (коды + названия);
- по каждой работе — отметки диагностики (риски, нужные запчасти);
- минимум свободных комментариев;
- всё, что нужно для выполнения, — в наряде; спрашивать принимавшего не требуется.

### 5. Выполнение

Перед началом работы, если она затрагивает посадку (руль, вынос, штырь, седло,
тормозные ручки), **зафиксировать текущие настройки байкфита**: положение и
вылет подседельного штыря, положение седла (отступ, угол), положение и угол
тормозных ручек. Отметки — в наряд, при возможности фото. Собрать после ремонта
в те же положения.

Мастер берёт наряд, отмечает выполнение операций, фактическое время (таймер),
израсходованные запчасти, отклонения от тех. карты. Найденные доп. работы →
назад на шаг 3 (согласование), в работу только после подтверждения клиента.

### 6. Повторная диагностика, ОТК и выдача

**Повторная диагностика после ремонта обязательна** — тот же прогон, что при
приёмке, плюс проверка моментов затяжки ответственных болтов (см. функцию
`Повторная диагностика (после ремонта)` в `procedures/intake.md`). Затем проверка
по критериям приёмки из тех. карт и выдача; клиенту — перечень выполненного.

## Открытые вопросы

- Кто делает диагностику: выделенный приёмщик или свободный мастер по очереди?
- Нужен ли письменный акт по `DIA-03` (авария) — для страховых/гарантийных
  случаев и для спортсменов?
- Платная ли диагностика, если клиент не оставляет велосипед в ремонт.
