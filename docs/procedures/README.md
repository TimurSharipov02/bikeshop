# Алгоритмы ремонта — библиотека процедур

Статус: черновик · Дата: 2026-09-10

Каждая процедура ремонта описана как **функция**: последовательность действий с
условиями (`ЕСЛИ`), циклами (`ПОКА`, `ДЛЯ КАЖДОГО`) и вызовами других функций
(`ВЫЗОВ`). Цель — формальный, однозначный алгоритм, по которому работает любой
мастер, и из которого потом собирается интерфейс приложения.

Каждая функция соответствует операции из `../work-taxonomy.md` (поле «Код операции»).

> **Рабочий источник — `catalog/*.proc`** в корне проекта (машинный формат,
> его грузит приложение). Эти `.md` — читаемая версия; правки с прогонов сначала
> идут в `.proc`, потом сверяются сюда. Возможно небольшое расхождение.

## Файлы по группам

| Файл | Группа | Статус |
|---|---|---|
| `intake.md` | DIA — приёмка и диагностика | 2 функции |
| `drv.md` | DRV — трансмиссия | 8 функций |
| `brk.md` | BRK — тормоза | 8 функций (BRK-08 — черновик) |
| `whl.md` | WHL — колёса, покрышки, бескамерка | 8 функций |
| `hub.md` | HUB — втулки, барабаны, оси | 4 функции |
| `sus.md` | SUS — подвеска | заглушка (по мануалам Fox / RockShox позже) |
| `str.md` | STR — рулевая, кокпит, проводка | 8 функций (STR-08 — без статьи Park Tool) |
| `bb.md` | BB — каретка, шатуны, педали | 6 функций + 3 вспомогательные (снятие шатунов) |
| `frm.md` | FRM — рама | 5 функций (FRM-04 — без статьи Park Tool) |
| `wsh.md` | WSH — мойка и консервация | 3 функции |
| `el.md` | EL — электронные группы | 4 функции (Shimano + SRAM; прочие — по мануалу) |
| — | BUILD | не начат; пакеты ТО отложены |

Помимо функций с кодами операций, в файлах есть **вспомогательные функции**
(без кода) — переиспользуемые куски, которые вызываются из нескольких мест
(напр. снятие/установка шатунов в `bb.md`).

Пакеты ТО (группа TO) пока не делаем — это композиции из других функций,
отложено как усложнение.

## Нотация

```
ФУНКЦИЯ Название(параметр: вариант1 | вариант2)
  Код операции : XXX-00
  Вход         : что должно быть верно до старта
  Инструмент   : список
  Расходники   : список
  ---
  1. Действие.
  2. ЕСЛИ <условие> ТО
       2.1. Действие.
     ИНАЧЕ ЕСЛИ <условие> ТО
       2.2. Действие.
     ИНАЧЕ
       2.3. Действие.
     КОНЕЦ ЕСЛИ
  3. ПОКА <условие> ПОВТОРЯТЬ
       3.1. Действие.
     КОНЕЦ ПОКА
  4. ДЛЯ КАЖДОГО <x> В <набор>:
       4.1. Действие с <x>.
     КОНЕЦ ДЛЯ
  5. ВЫЗОВ Другая функция(аргументы).
  6. ПРОВЕРИТЬ: критерий приёмки.
       ЕСЛИ НЕ выполнено → вернуться к шагу N / согласовать с клиентом / СТОП.
  ---
  ПРОВЕРКА КАЧЕСТВА:
    - критерий 1
    - критерий 2
  ФИКСИРОВАТЬ В НАРЯДЕ:
    - что записать по факту
КОНЕЦ ФУНКЦИИ
```

Служебные слова:
- `ВЫЗОВ` — выполнить другую функцию (переиспользование).
- `СОГЛАСОВАТЬ С КЛИЕНТОМ` — работа выходит за рамки наряда, нужен звонок/ответ.
- `СТОП` — дальше не продолжать (небезопасно / нужен старший механик).
- `ЗАМЕТКА:` — пояснение «как и почему», не действие.

Ссылка на другую функцию в тексте — по коду в квадратных скобках, напр. `[DRV-07]`.

## Уровни детализации (для приложения)

Каждая функция имеет 3 уровня вложенности. Приложение показывает шаги с
регулируемой подробностью — как в Photomath (можно идти крупными шагами, можно
разложить каждый на мелкие):

- **Уровень 0 — Глава.** Крупный этап («H-лимит», «Индексация») + контрольные
  точки `ПРОВЕРИТЬ`.
- **Уровень 1 — Шаг.** Нумерованное действие внутри главы.
- **Уровень 2 — Детализация.** Под-шаги, точные величины (обороты, мм, Н·м),
  `ЗАМЕТКА` с пояснением.

Режимы отображения:
- **Мастер** — только Уровень 0 + `ПРОВЕРИТЬ`.
- **Стандарт** — Уровни 0–1.
- **Обучение** — всё, включая `ЗАМЕТКА`.

Мастер может листать по главам, пропускать их, разворачивать любой шаг глубже.
Нумерация строго согласованная: `Глава N` → `шаг N.M` → `под-шаг N.M.K`.
