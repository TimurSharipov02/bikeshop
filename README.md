# Веломастерская Veloterra

Рабочий процесс мастерской — от приёма велосипеда до выдачи.

- Концепция и решения — `docs/vision.md`
- Справочник видов работ — `docs/work-taxonomy.md`
- Процесс приёмки — `docs/intake-flow.md`

## Приложение

`npm run build` собирает всё в **один HTML** (данные, стили, код внутри):
- `veloterra.html` — открыть двойным кликом локально;
- `public/index.html` — то же, для хостинга.

Обычный ванильный JavaScript, без фреймворков. Сборка — обычный Node,
без пакетов (`scripts/build-html.js`).

```
npm run build        # → veloterra.html + public/index.html
npm test             # синхронизация данных, права доступа, расчёт для 1С
```

Все ремонтные работы (название, цена, время, усложнения) заводит
администратор вручную прямо в приложении — экран диагностики, кнопка «+
своя неисправность» (✎/✕ там же — правка и удаление). Список узлов
велосипеда для группировки (Колёса, Тормоз, Каретка…) правится в
`catalog/diagnostics.json`.

### Хостинг на Vercel + общее хранилище

- `vercel.json` — framework = none, build = `npm run build`, output = `public`.
- `api/db.js` — серверная функция: держит данные в **Upstash Redis**.
  Независимые правки с разных устройств объединяются по полям и работам;
  одновременная правка одного поля возвращает конфликт. Запись атомарна.
- Приложение (`web/app.js`) хранит данные и локально (мгновенно, работает
  оффлайн), и на сервере (`/api/db`) — общие для всех. Синхронизация при
  каждом переходе между экранами.
  Несохранённые локальные правки остаются на устройстве до успешной отправки.

Развернуть:

1. Залить проект на GitHub, подключить репозиторий к Vercel («Import Project»).
2. В проекте Vercel → вкладка **Storage** → **Create** → **Upstash for Redis** →
   привязать к проекту. Переменные окружения (`UPSTASH_REDIS_REST_URL` /
   `UPSTASH_REDIS_REST_TOKEN`) проставятся автоматически.
3. **Redeploy**.

Пока Upstash не подключён, приложение работает на локальном хранилище браузера
(данные не общие) — всё функционирует, просто без синхронизации.

Ручной каталог работ и остатки запчастей также хранятся на сервере и
одинаковы на всех устройствах.

## Структура

```
catalog/diagnostics.json  узлы велосипеда (id/title/перед-зад) для группировки работ
web/
  app.js             всё приложение (обычный JS: роутер, экраны, наряд)
  pricing.js         общий расчёт работы для приложения и выгрузки в 1С
  report-entries.js  разбор истории выработки по мастерам
  app.css            стили
  template.html      каркас
scripts/
  build-html.js      сшивает всё в veloterra.html (обычный Node, без зависимостей)
api/
  db.js              общая база (Upstash Redis)
  _db-merge.js       слияние независимых правок клиентов, велосипедов и работ
  _atomic-db.js      атомарное сохранение общей базы в Redis
  _work-access.js    права доступа к работам заявки
  repairs.js         каталог работ, заводимых администратором вручную
  stock.js           остатки запчастей
  users.js           мастера и администраторы
  auth.js            вход/сессия
  1c-export.js       выгрузка выполненных работ для 1С
tests/               проверки синхронизации, авторизации и выгрузки для 1С
docs/                документация проекта
```

## Что умеет приложение

- **Новый наряд** — выбор работ из раскрывающихся блоков узлов велосипеда;
  клиент, телефон и велосипед необязательны и заполняются после списка работ.
- **Работа** — самостоятельная задача с ценой, количеством, усложнениями,
  запчастями, ожиданием детали и мастером, который отметил её готовой.
- **Количество работы** — три режима: одна задача, отдельные одинаковые
  задачи (с необязательным максимумом) или одна задача с числовым количеством.
- **Оценка** — возле работы показывается базовая цена со знаком `+`, а в
  итоговом блоке — полная вилка с учётом ещё не определённых усложнений.
- **Ремонт** — уточнения, список работ, добавление новых работ по тем же
  блокам, изменение клиента/телефона/велосипеда и выдача после завершения.
- **Админка** — мастера, клиенты, отчёты и склад запчастей.
