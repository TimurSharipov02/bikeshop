# Веломастерская Vella

Рабочий процесс мастерской и раннер технологических процедур.

- Концепция и решения — `docs/vision.md`
- Справочник видов работ — `docs/work-taxonomy.md`
- Процесс приёмки — `docs/intake-flow.md`
- Алгоритмы ремонта (проза) — `docs/procedures/*.md`

## Приложение

`npm run build` собирает всё в **один HTML** (данные, стили, код внутри):
- `vella.html` — открыть двойным кликом локально;
- `public/index.html` — то же, для хостинга.

Обычный ванильный JavaScript, без фреймворков. Сборка — обычный Node,
**без пакетов и без TypeScript** (`scripts/build-html.js`).

```
npm run build        # → vella.html + public/index.html
npm run cli          # консольная версия рабочего процесса
npm run check        # validate + dryrun + audit каталога процедур
```

Обновить процедуры/цены: правишь `catalog/*.proc` или `catalog/prices.json`
→ `npm run build`.

### Хостинг на Vercel + общее хранилище

- `vercel.json` — framework = none, build = `npm run build`, output = `public`.
- `api/db.js` — серверная функция: держит все данные одним JSON в **Upstash
  Redis**, при записи сливает правки с разных устройств.
- Приложение (`web/app.js`) хранит данные и локально (мгновенно, работает
  оффлайн), и на сервере (`/api/db`) — общие для всех. Синхронизация при
  каждом переходе между экранами.

Развернуть:

1. Залить проект на GitHub, подключить репозиторий к Vercel («Import Project»).
2. В проекте Vercel → вкладка **Storage** → **Create** → **Upstash for Redis** →
   привязать к проекту. Переменные окружения (`UPSTASH_REDIS_REST_URL` /
   `UPSTASH_REDIS_REST_TOKEN`) проставятся автоматически.
3. **Redeploy**.

Пока Upstash не подключён, приложение работает на локальном хранилище браузера
(данные не общие) — всё функционирует, просто без синхронизации.

**Прайс-лист** остаётся локальным на устройстве (не критично — правится редко).

## Структура

```
catalog/*.proc       процедуры в своём текстовом формате (см. src/dsl.ts)
catalog/faults.json  типовые неисправности по узлам
catalog/prices.json  прайс: работа + надбавки за трудности
web/
  app.js             всё приложение (обычный JS: роутер, экраны, наряд)
  runner.js          движок процедур в браузере
  app.css            стили
  template.html      каркас
scripts/
  gen-catalog.ts     catalog → web/catalog.json
  build-html.js      сшивает всё в vella.html (обычный Node, без зависимостей)
src/                 ядро на TS: парсер, движок, домен, консоль, проверки
docs/                документация проекта
data/db.json         данные консольной версии (gitignored)
```

## Что умеет приложение

- **Обращение** — опросник (клиент по телефону, велосипед с генерацией номера `B-…`), номер обращения `V…`.
- **Диагностика** — листаемый чек-лист по узлам; на пункте «Проблема» раскрывается список неисправностей → работы падают в наряд.
- **Оценка** — по каждой работе возможные трудности (будет / не будет / неизвестно) → вилка цены «от … до …».
- **Согласование → ремонт** (раннер ведёт по процедуре, отметки: время, запчасти, кто) **→ повторная диагностика → выдача**.
- **Прайс-лист** правится прямо в приложении.

## Формат процедуры (.proc)

`PROC <код> "имя"` с параметрами, главами (`CH`), шагами (`STEP`/`SUB`/`NOTE`),
ветвлением (`IF`/`ELIF`/`ELSE`/`END`), циклами (`WHILE`, `FOREACH`), вызовами
(`CALL`), проверками (`CHECK [ГРУППА] … — норма?`), `APPROVE`, `STOP`, блоками
`QUALITY`/`RECORD`/`SOURCE`. Подробно — в шапке `src/dsl.ts`.

Раннер показывает шаги с регулируемой детализацией: **Мастер** (только главы и
проверки), **Стандарт**, **Обучение**.
